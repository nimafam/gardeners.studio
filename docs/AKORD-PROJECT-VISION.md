# AKORD Website — Project Vision

## What Is AKORD?
AKORD is an international business development company. It helps businesses establish, shape, communicate, grow, and extend themselves across stages of development.

AKORD is not positioned simply as a branding agency, digital agency, advertising agency, or consultancy. Its services form an interconnected business development system.

## Central Brand Metaphor
The conceptual foundation of AKORD is music. The name relates naturally to **Chord**.

A chord is not a single sound; it is several distinct notes arranged into a coherent relationship.

A successful organization also consists of multiple systems—strategy, identity, digital presence, communication, promotion, innovation, operations. Individually they may function. Together they must become a composition.

## AKORD's Role

### Composer
AKORD helps determine:
- what should exist
- how parts relate
- what the structure should be
- what the business should communicate

### Conductor
AKORD coordinates execution across:
- disciplines
- teams
- channels
- systems
- markets
- touchpoints

AKORD therefore does not merely create isolated deliverables. It helps create coherence.

## Brand Statement
> Every Business Deserves a Perfect Composition.

## Website Objective
The AKORD website should not behave like a conventional corporate website made of stacked Hero, About, Services, Projects, and Contact sections with generic reveal animations.

The website itself should demonstrate the AKORD idea.

The visitor should experience:
separate elements → relationships → structure → composition → transformation → coherent system.

## The Website as a Composition
The website should feel closer to entering a composed environment than reading a brochure. Scrolling is not merely page movement; it acts as navigation through a spatial narrative.

## Experience Principle
The user moves through conceptual environments. Each environment communicates an idea. Motion explains how one concept becomes another.

**Animation is not decoration. Animation is information.**

## Spatial Direction
The experience should create depth, layers, spatial relationships, movement through a system, transformation, and continuity.

Simple parallax is not sufficient for the core experience. WebGL / Three.js / spatial rendering can be used where it meaningfully creates genuine depth.

## Restraint
Immersive does not mean chaotic.

AKORD should remain:
- minimal
- sophisticated
- editorial
- controlled
- premium
- calm

Avoid turning the website into a technology demo.

## Motion Character
Motion should feel composed, deliberate, elegant, weighted, spatial, and musical.

Avoid random floating objects, excessive elastic motion, unnecessary particle effects, generic parallax, constant purposeless movement, and animation that competes with reading.

## Musical Rhythm
A composition contains movement, silence, tension, release, repetition, and variation. The website should therefore include intentional stillness. A pause can be part of choreography.

## User Control vs Choreography
The user determines intent—continue, return, explore—but some transitions should execute as complete gestures.

> Navigation may be user-driven while choreography can be system-driven.

## Main Experience Direction
The top-level journey includes major conceptual sections such as Hero, About, Services, and later content/work/company experiences. The exact production sitemap must come from current project documentation and repository implementation.

## Services as an Internal Journey
Services is not intended to be a standard grid of cards. Entering Services begins another internal experience.

There are exactly five primary groups:
1. Core
2. Identity
3. Digital
4. Promotion
5. Edge

## Service Sequence as Narrative

### Core
The foundation. The score. The underlying structure of the business.

### Identity
The recognizable voice. What makes the organization distinct and coherent.

### Digital
The stage. Where identity becomes interactive and performs.

### Promotion
Amplification. The movement of the message outward.

### Edge
Advantage and differentiation. The point where accumulated capability becomes competitive leverage.

## Services Are Not Five Slides
Each Service should have its own spatial logic and visual behavior, while all five still feel like movements inside one composition.

## Transition Meaning
Transitions should express conceptual transformation:
- Core → Identity: structure becomes expression
- Identity → Digital: voice becomes transmission and performance
- Digital → Promotion: presence becomes reach
- Promotion → Edge: amplification becomes concentrated advantage

These are conceptual directions, not literal animation instructions.

## Identity → Digital Reference
A key reference transition developed around:

resonance → transmission → stage

This helped establish that Service handoffs should be continuous transformations rather than isolated animation screens.

## Content Hierarchy
Example:

02 — **Identity** · *The Voice*

The Service name is primary. The metaphorical descriptor is secondary. Do not make “The Voice” visually more important than “Identity”.

## Typography
- Titles: Kento
- Subtitle / Body: Ubuntu

Typography should remain clean and editorial.

## Brand Colors
Primary: `#01362E`

Accent: `#BB987D`

Use existing design tokens where available.

## Iconography
Preferred icon system: Vusax — Bulk.

Icons should remain secondary to typography and composition.

## Visual Identity Direction
The visual identity combines minimalism, strong typography, dark/light contrast, spatial composition, subtle premium detailing, and controlled motion. Avoid generic corporate visual language.

## Technology Direction
Known project direction includes:
- Next.js
- React
- TypeScript
- Tailwind
- reusable component architecture
- Headless CMS integration
- WebGL / Three.js where meaningful

The repository is the source of truth for exact versions and package structure.

## Broader Architecture
The broader project has followed a monorepo direction with a web application, API/backend, shared packages, and reusable UI/types/config/utilities. Do not redesign the monorepo based only on this document.

## CMS Philosophy
The final website must remain manageable through a Headless CMS. Immersive presentation and structured content should remain separated where possible. The Experience Engine should not force editorial content into hard-coded animation data.

## Reusability
The system should eventually support reusable sections, content structures, visual primitives, motion primitives, transitions, and CMS mappings. Abstraction must follow proven repetition; do not prematurely generalize unique choreography.

## Experience Engine
The Experience Engine translates:

scroll/navigation intent + content + scene state + motion rules

into a coherent visual journey.

It should not become a collection of unrelated `useEffect` animations.

Think:

INPUT → NAVIGATION INTENT → EXPERIENCE STATE → CHOREOGRAPHY → VISUAL SCENE

not:

scroll event → change CSS property.

## Scroll
Scroll is one input mechanism. It should not become the architecture itself, especially for cinematic transitions.

## Performance
The immersive nature of the site does not justify poor performance. Motion must remain responsive and visual complexity must contribute meaningfully to the experience.

## Responsive Design
The Experience must eventually account for desktop, laptop, tablet, mobile, reduced-motion preferences, and different input devices. Wheel-based desktop interaction is not the final universal interaction model.

## Accessibility
Future production implementation must consider reduced motion, keyboard navigation, readable contrast, semantic content, content accessibility without animation, and fallback behavior.

## Design Reference Philosophy
External websites may inspire pacing, spatial sophistication, restraint, and interaction quality, but should not be copied. AKORD requires its own motion language based on its musical/compositional identity.

## What AKORD Should Feel Like
A visitor should ideally experience:

> “I am moving through a system that is being composed around me.”

not:

> “I am scrolling through a website with animations.”

## What AKORD Should NOT Feel Like
Avoid making it feel like a template, slide deck, generic agency portfolio, particle demo, Three.js experiment, collection of scroll tricks, or conventional landing page with excessive animation.

## Final Experience Goal
The visual, narrative, and technical systems should converge on one idea:

**Many distinct capabilities becoming one coherent composition.**

That is the relationship between AKORD the brand and AKORD the website.
